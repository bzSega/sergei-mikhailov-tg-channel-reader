# task-0004 — Session hardening: non-interactive auth check, locking, last-known-good recovery

**Status:** done (2026-07-02)

## Context

Incident on 2026-07-02: after a VM restart, the OpenClaw bot reported the
Telegram session as "expired". Investigation showed the session was **alive on
Telegram's side** — the local session file with the working auth key had been
destroyed by multiple agents (main session + cron) running `tg-reader`
concurrently: they raced over the same SQLite session file, rewrote the config,
renamed/deleted session files, and left only never-authorized copies behind.

Root causes confirmed against the 0.9.4 code:

- **RC1** — `fetch`/`info` in the Pyrogram backend validate only that the
  session *file exists*, then enter `async with Client(...)` which calls
  `start()` → interactive phone prompt when the session is not authorized.
  In cron this hangs or dies with `EOFError`, and the client has already
  opened the SQLite session for writing. (The Telethon backend already used
  `connect()` + `is_user_authorized()`, but returned an unstructured error.)
- **RC2** — no file locking; concurrent `tg-reader` processes corrupt the
  SQLite session.
- **RC3** — session-not-found errors suggested "use the freshest found
  session file" (sorted by mtime), which agents follow blindly, causing
  path drift between dot/non-dot session names.
- **RC4** — `auth` overwrites the session file with no backup.
- **RC5** — no `not_authorized` error type; agents invented explanations
  ("TTL 30 days", "Telegram revoked") for a generic failure.
- SKILL.md literally instructed `rm -f ~/.tg-reader-session.session` as the
  session-expired remedy — the exact destructive action agents performed.

Fix proposal was drafted by the user's bot and reviewed here; amendments made
during review: network errors must not be conflated with `not_authorized`;
Telethon backend needs parity; no breaking config changes (the `session` key
stays optional, default path stays canonical); online authorization check goes
behind an opt-in `tg-reader-check --online` flag (default stays offline);
`auth` does not auto-write the config file. Added FIX-7 (last-known-good
backup + explicit `restore-session` command) per user request.

## Plan

1. **FIX-1** — non-interactive authorization check in the Pyrogram backend:
   `connect()` (returns authorized bool, never prompts) + `get_me()` guarded
   by `pyrogram.errors.Unauthorized`. Honest error split: `not_authorized`
   vs `network`. `sys.stdin = devnull` backstop for `fetch`/`info`/`restore`.
   Telethon: structured `not_authorized` error (mechanism already existed).
2. **FIX-2** — exclusive `flock` around any session use (fetch/info/auth/
   restore, both backends; POSIX-only, no-op fallback elsewhere). Second
   process gets `error_type: "busy"` after a bounded wait.
3. **FIX-3 (softened)** — session-not-found errors list found candidates but
   no longer auto-suggest the freshest file; they point to
   `tg-reader-check --online` instead. No config schema changes.
4. **FIX-4** — `auth` makes a timestamped backup of an existing session file
   first (0600, rotation keep-3) and verifies with `get_me()` after.
5. **FIX-5** — closed `error_type` list gains `not_authorized`, `busy`,
   `network`. `tg-reader-check --online` verifies actual authorization for
   the resolved session (under the lock); offline mode also reports lock
   state and last-good backup metadata.
6. **FIX-6** — SKILL.md policy: background/scheduled runs never auth,
   restore, delete, or move session files — notify the user instead. The
   destructive `rm -f` advice is removed.
7. **FIX-7** — last-known-good session backup: after every successful
   authorized run the session file is copied (0600) to
   `{session}.session.last-good` with a no-secrets JSON manifest
   (verified_at, user id/name, sha256). New `restore-session` command
   restores it explicitly (moves the broken file aside, verifies, reports).
   `not_authorized` errors advertise the backup with `action: offer_restore`.

New shared module `tg_session_guard.py` (no heavy deps) hosts lock + backup +
last-good logic for both backends. Version bump 0.9.4 → 0.10.0.

## Result / outcome

Delivered in PR #9 against `main`, version 0.9.4 → 0.10.0.

New shared module [tg_session_guard.py](../tg_session_guard.py) (no heavy deps)
holds the lock, timestamped backups with rotation (keep 3, 0600), and the
last-known-good snapshot/restore. Temp files are opened `O_CREAT|O_EXCL` at
mode 0600 from the first byte — no default-umask window.

- **FIX-1** — [reader.py](../reader.py) `_authorized_client` connects with
  `connect()` + `get_me()`, never `start()`; raises `NotAuthorizedError` vs
  `NetworkError`, never conflated. Non-interactive commands detach stdin as a
  backstop. The Telethon backend
  ([reader_telethon.py](../reader_telethon.py)) already connected
  non-interactively; its unauthorized path is now structured too.
- **FIX-2** — exclusive `flock` via `session_lock` wraps the whole dispatch in
  both `main()`s; a second process returns `error_type: "busy"`. POSIX-only,
  no-op fallback elsewhere.
- **FIX-3 (softened)** — session-not-found hints no longer auto-suggest the
  freshest file; they point at `tg-reader-check --online`. No config schema
  change (the `session` key stayed optional, default path unchanged).
- **FIX-4** — `auth` backs up an existing session first and verifies with
  `get_me()`.
- **FIX-5** — [tg_check.py](../tg_check.py) gained `--online` (authorization
  probe under the lock); offline mode reports lock state and last-good
  metadata. `_check_credentials` now returns the resolved credentials so the
  online path reuses one resolution.
- **FIX-6** — [SKILL.md](../SKILL.md) "Session Safety Rules": background runs
  never delete/move sessions or attempt auth/restore — notify the user. The
  destructive `rm -f` session-expired advice was removed.
- **FIX-7** — after every verified-authorized run `_authorized_client`
  snapshots the session as `{session}.session.last-good` (+ no-secrets
  manifest). New `restore-session` subcommand restores it: broken file moved
  aside (never deleted), backup checksum-verified, then re-verified against
  Telegram.

Reviews on PR #9:
- `/security-review` — 0 vulnerabilities. One umask-timing candidate
  (temp file created before `chmod`) was reviewed and hardened preemptively
  (commit `da25679`).
- `/code-review` (high effort) — found and fixed a real bug: `fetch_info`
  returned channel errors from inside the `async with`, skipping the last-good
  snapshot even though the session was verified authorized. Fixed by moving the
  snapshot into `_authorized_client` (commit `615f586`), which also collapsed a
  9-site scatter to 4 principled sites. Also merged the Telethon
  `_authorized_client` split try-blocks (a non-sqlite constructor error had
  escaped as a raw traceback) and deduped the credential resolution in
  `tg_check`. Rejected: collapsing Telethon `is_user_authorized()` + `get_me()`
  to `get_me()`-only would have regressed the `not_authorized`/`network` split.

Post-publish: the user runs a live smoke test on the VM (first success creates
`.session.last-good`, then simulate corruption and `tg-reader restore-session`)
and updates the incident's stuck agent.

## Lessons

- The reported symptom ("session expired / revoked by Telegram") was the
  opposite of the truth — the session was alive server-side; the *local file*
  was destroyed by concurrent agents. When several diagnostics point at
  "Telegram invalidated us", check the "Active sessions" screen in the Telegram
  app before touching the local file. Cross-ref: this drove FIX-5's honest
  `not_authorized` vs `network` split and the "never invent causes" SKILL.md
  rule.
- A fix that a background agent can *misuse* is not a fix. The original
  incident was partly self-inflicted: agents "helpfully" moved session files
  and rewrote the config. FIX-6 encodes the policy (notify, don't repair) so
  the next incident doesn't repeat it.
- Snapshot-on-success belongs at the single choke point (`_authorized_client`),
  not scattered at each call site — the `fetch_info` miss the review caught was
  a direct consequence of scattering it. Right altitude beats copy-paste.
