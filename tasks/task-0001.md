# task-0001 — Audit project + add session workflow & task-tracking rules to CLAUDE.md

**Status:** in-progress (opened 2026-05-16)

## Context

User asked for a full state audit of the project, then progressively layered four additional policy requirements onto CLAUDE.md during the same session:

1. Surface the current state of the project in one place (audit) and update auto-memory + CLAUDE.md where they had drifted.
2. Enforce an end-of-session retrospective with mandatory memory updates so future sessions accumulate lessons instead of repeating mistakes.
3. Enforce a code-review-before-commit/push/deploy workflow (PR → `/review` → fix → only then commit / push / merge / deploy), motivated by past single-commit fixes that a review would have caught.
4. Introduce a `tasks/` folder convention with `task-NNNN.md` files plus an index in CLAUDE.md, so future queries about prior task history are answerable from CLAUDE.md alone.
5. Reinforce the open-source data-hygiene rule: this repo is public, everything written into it stays English-only and must not leak personal absolute paths, secrets, or other sensitive data.

This is task 0001 because the convention is being established in this very session — the work itself is the first task tracked under the new rule.

## Plan

1. **Audit** — run an Explore agent over the worktree to collect version, files, entry points, env vars, last 5 CHANGELOG entries, git state, README/SKILL.md/CHANGELOG synopsis, `.gitignore` patterns.

   - `project_overview.md` (type: project) — exact ClawHub publishing identifiers.
   - `reference_docs.md` (type: reference) — URLs to WebFetch before answering Pyrogram/Telethon/ClawHub questions.
   - `feedback_language.md` (type: feedback) — language rule for chat vs. repo content.
   - Update the memory index file with three new pointer lines.
4. **CLAUDE.md — Session workflow rules** — append a new section with two subsections: End-of-session retrospective, Code review before commit/push/deploy.
5. **CLAUDE.md — Task tracking rule + open-source hygiene** — append a section defining `tasks/` + `task-NNNN.md` + a Task index table. Strengthen the existing "Key conventions" block with explicit open-source rules (English-only on disk, no sensitive data, no host-local absolute paths in repo files). Create this file (`task-0001.md`) and register it in the index.

## Lessons

- Memory style preference confirmed: **minimal and targeted**, not "full state snapshot". The three new memory files were scoped to only non-derivable facts (publishing identifiers, external docs URLs, language preference).
- The legacy memory index file uses an inline-bullets format rather than the index-only pointer format the current memory spec describes. The existing legacy block was not rewritten — out of scope for "minimal". Flag for a future task if it ever needs reorganising.
- Drift between the real `.gitignore` and the CLAUDE.md shorthand is easy to miss; the new retrospective rule should catch this kind of doc-vs-code drift on future similar additions.
- **Open-source hygiene caught in flight.** The first draft of this very task file embedded host-local absolute paths (`/Users/<name>/...` style) and Russian-language quotes from the chat. Both got rewritten to placeholder phrasing and English-only summaries before the file was committed. The Key conventions block in CLAUDE.md now codifies this rule explicitly so the same drift cannot recur silently.
